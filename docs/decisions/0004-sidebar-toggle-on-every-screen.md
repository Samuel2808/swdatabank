# 0004 — Let the sidebar be hidden on every screen size (R9 changed)

Status: accepted (round 3). Changes the round 2 sidebar described in `spec.md` ("Sidebar menu (R9, R10)"); does not replace another decision record.

In the context of R9, which in round 2 made the section menu a fixed 220 px sidebar that was always shown at 768 px and wider and could only be hidden below 768 px, and which the owner changed in round 3 so that the sidebar can be hidden and shown on every screen size, with the content using the freed width,
facing the choice between one top bar and button for all sizes or a second, desktop-only button inside the sidebar; between pushing the content aside or laying the sidebar over it on wide screens; and between remembering the visitor's choice or starting from a fixed default,
we decided for one top bar, now shown on every screen size, with one button labelled "Menu" / "Hide menu"; on wide screens the open sidebar pushes the content aside and closing it gives the width back (the content panel may now grow to 1400 px), and only the button changes it there; below 768 px it still opens over the content with a scrim and closes on a link, Escape or the scrim; the state starts open on wide screens and closed on narrow ones on every load, and resets when the window crosses 768 px; the rules stay in the pure function `nextMenuState(open, action, wide)` plus `menuStartsOpen(wide)`,
and neglected a second button inside the sidebar (two controls for one thing, and nothing to press once the sidebar is gone), an overlay on wide screens too (it would cover the content instead of freeing width, which R9 now asks for), closing on every link on wide screens (the menu would vanish each time you browse), and remembering the choice in `localStorage` (R9 says how it starts; a stored choice would make the start state differ between visits and need more tests),
to achieve one way to show and hide the menu everywhere, content that really gets wider when the menu is hidden, and logic that is still a small tested pure function,
accepting that the top bar now takes 56 px at the top of wide screens too, that the round 2 tests "the menu always closes" and "hidden only below 768 px" are replaced, and that a visitor who hides the sidebar on a wide screen sees it again on the next load.
