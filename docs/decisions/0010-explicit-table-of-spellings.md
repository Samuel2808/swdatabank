# 0010 — Merge filter spellings with an explicit table per filter

Status: accepted (round 6)

In the context of R23, which asks that spelling variants in the data (such as "Galatic Basic" next to "Galactic Basic") be shown as one filter option, in filters (R19) whose option values have been part of shared links since R20, over a bundled SWAPI snapshot that a developer can refresh with `scripts/fetch-data.mjs`,
facing the options of an explicit table of spellings on each filter in `FILTERS` (`same`: groups of spellings, the first one shown); automatic merging by a similarity rule (edit distance of one or two letters, or ignoring spaces and punctuation); automatic merging by a stemming rule (dropping a final "s", "es", "Inc."); and correcting the bundled JSON files themselves,
we decided for the explicit table: eleven groups agreed with the owner (Galactic Basic, two manufacturers with and without "Inc." / "Incorporated", airspeeder, mammal, and six singular/plural terrains), each one option whose label is the spelling most entries use; `canonicalValue` turns any spelling, and the old "not listed" of the renamed "Unknown species" option, into the option value, so links made before this round still select the merged option,
and neglected a similarity rule (with values this short it would also merge words that really differ within one filter: the genders "male" and "female", the terrains "rock" and "rocky", the climates "artic" and "arid" are each one or two letters apart; and which options merge would change silently whenever the data is refreshed), a stemming rule (dropping a final "s" or a company suffix handles most plurals and "Inc.", but not "Galatic Basic", "air speeder" or "savannahs", so a table would still be needed for those), and editing the data files (R5 asks that a detail page show every fact the data holds, and `fetch-data.mjs` would overwrite the fixes on the next refresh),
to achieve dropdowns without duplicate options whose every merge is a choice someone made and can read in one place, with tests that check each spelling in the table is really in the data and that the label is the most common spelling, while detail pages still show the data as it is,
accepting that a new variant in refreshed data is not merged until someone adds it to the table (a test fails if a listed spelling disappears, but not when a new one appears); that the table is more data to keep in `js/sections.js`; and that the option values of the merged spellings (`galatic basic`, `desert`…) are now old values, accepted on the way in but never written into new links.
