# 0012 — Draw the favorite star as text in the one card builder, from the favorites store

Status: accepted (round 7)

In the context of R24, which asks that the cards of favorites show a star in every list of entries (section lists, search results and the Favorites page), in a site where favorites live in a store read from `localStorage` (R18), every card list is drawn again whenever it is shown, the site is black and white (R14), and icons are inline SVG drawn for this project (R10),
facing the options of adding the star while building each card in the single `cards()` function, from a pure `markFavorites(entries, favorites.list())`; marking the cards with a `data-favorite` attribute and drawing the star with CSS `::after { content: "★" }`; drawing the star as a new inline SVG icon; and making the star a button that adds or removes the favorite from the list,
we decided for a "★" text character in an `aria-hidden` span in the card's top-right corner, followed by a visually hidden " (favorite)", both added by `cards()` from `markFavorites`,
and neglected the CSS `::after` star (generated content is read inconsistently by screen readers, so the favorite would have no reliable text, and the rule that decides who gets a star would sit in CSS where no test can run it), a new SVG icon (more markup for a shape the font already draws, and the detail page's button already uses the "★" character, so the two would not match), and a clickable star (R24 asks only that favorites can be seen; a button inside a card link is invalid HTML and would need the card's structure changed, and the owner chose a display-only star),
to achieve one place that builds every card, so section lists, filtered lists, search results and the Favorites page cannot drift apart, with the favorite test as a pure function tested without a browser, and the same star the detail page's button already shows,
accepting that the star's look depends on the visitor's font, that every card keeps 28 px of right padding even when it has no star, and that a star only changes when the list is drawn again (it does not change on a list that is already on screen if favorites change in another tab).
