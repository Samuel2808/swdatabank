# 0006 — Test the 375 px layout by reading the CSS, not with a headless browser

Status: accepted (round 4)

In the context of R8 (changed in round 4), which asks for automated tests that no part of the layout is wider than 375 pixels and that long names and words wrap, in a project whose tests run with Node's built-in runner, with nothing to install and no browser (`CLAUDE.md`),
facing the options of reading `index.html` and `styles.css` and checking the size rules a 375 px screen would use; adding Playwright or Puppeteer as a development dependency to load every view at 375 px and compare `scrollWidth` with the window width; and a script that drives the Chrome already installed on the machine through its debugging protocol,
we decided for static checks in `tests/layout.test.js`: a device-width viewport; no `width`, `min-width`, `flex-basis` or `minmax()` column outside the wide-screen media blocks whose smallest possible size is over 375 px (with `rem`, `clamp`, `min`, `max`, `%`, `vw` and custom properties worked out); `overflow-wrap: anywhere` on the body and no `white-space: nowrap` outside screen-reader text; clipped animation layers; and `max-width: 100%` on the new dropdowns and buttons,
and neglected a headless browser (the most faithful check, but it adds a large download and a `node_modules` folder to a project that has neither, makes `npm test` slow and dependent on a browser build, and breaks the rule that tests need nothing installed) and driving the local Chrome (no install, but tests would fail or be skipped on any machine without Chrome, such as a grader's, and would need a server running),
to achieve R8 tests that run in a fraction of a second on every `npm test`, on any machine with Node, and that fail as soon as a fixed width wider than a phone is added (checked by adding `width: 500px` by hand),
accepting that the tests check the rules that cause horizontal scrolling rather than measuring a rendered page, so a cause they do not model (for example a wide inline element added by JavaScript or an unbreakable image) could still slip through; that is why the hand check at 375 px in the browser stays, and why a real-browser test remains an option if the project ever accepts development dependencies.
