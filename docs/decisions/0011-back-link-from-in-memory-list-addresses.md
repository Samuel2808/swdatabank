# 0011 — Build the back link from each section's last list address, kept in memory

Status: accepted (round 6)

In the context of R22, which asks that the "← Section" link on a detail page return to the section list with the filters and name search the visitor had before opening the entry, in a site whose list filters live in the address since R20 (decision 0009) and where a visitor often reaches an entry through related links from other sections (R6),
facing the options of remembering each section's last list address in a variable in the page and using it as the link's `href`; making the link call `history.back()`; putting the list's filters into the detail page's own address (`#/people/1?from=…`); and keeping the remembered addresses in `localStorage` or `sessionStorage`,
we decided for an in-memory record: every time a section list updates, `rememberList` stores its address (rebuilt by `listHash` from what `parseListState` accepts) under its section, and the back link's `href` is `backHref(memory, section)`, the remembered address or the plain section; nothing is stored, so a reload forgets it,
and neglected `history.back()` (it returns to whatever page came before, which after a related link is another entry or another section, not this section's list, and it does nothing useful on a page opened from a shared link), the filters in the detail page's address (every related link would have to carry them, addresses of entries would no longer be one per entry, and a shared entry link would carry someone else's filters), and browser storage (`CLAUDE.md` allows only `localStorage` under `swdatabank.` keys, and filters surviving a reload or a new visit is more than R22 asks; it would also be a third key whose format must be kept forever),
to achieve a back link that is an ordinary link (it can be copied or opened in a new tab), that returns to the section's last filters however the visitor reached the entry, with the remembering rules as pure functions tested without a browser,
accepting that the memory is lost on a reload or in a new tab, so a detail page opened from a link goes back to the plain section; that following the link adds a history entry instead of stepping back; and that the list opens at the top, not at the scroll position the visitor left.
